# 租赁收益分析

CS 饰品除了低买高卖，还有第二条收益路径：**出租收租**。本工具把租金、市场波动、
手续费、流动性合成一个可比较的结论。

```bash
python -m csmon rent scan            # 采集关注清单里所有饰品的租赁数据
python -m csmon rent show "★ M9 Bayonet | Doppler (Factory New)"
python -m csmon rent rank            # 按年化收益排行
```

---

## 一、数据从哪来

**CSQAQ 的「获取单件饰品详情」接口**（授权 API，一次请求拿全）：

```
GET https://api.csqaq.com/api/v1/info/good?id=<good_id>
Header: ApiToken: <token>
```

返回的租赁相关字段：

| 字段 | 含义 |
| --- | --- |
| `yyyp_lease_price` | **短租日租金** |
| `yyyp_long_lease_price` | **长租日租金** |
| `yyyp_lease_annual` | 短租年化率（平台口径，%） |
| `yyyp_long_lease_annual` | 长租年化率（平台口径，%） |
| `yyyp_lease_num` | 出租挂单数（出租竞争程度） |
| `yyyp_transfer_price` | 转租价 |
| `yyyp_sell_price` / `buff_sell_price` / `steam_sell_price` | 各平台在售价 |
| `yyyp_sell_num` / `statistic` / `turnover_number` | 在售量 / 存世量 / 成交量 |
| `sell_price_rate_{1,7,15,30,90,180,365}` | 各周期涨跌幅（%） |

**附带收获**：同一个接口的 `dpl` 数组直接给出**相位 ↔ paint_index 映射**：

```
红宝石 → 415    蓝宝石 → 416    黑珍珠 → 417
Phase1 → 418     Phase2 → 419    Phase3 → 420    Phase4 → 421
```

这补上了之前「不预置种子表」缺的那张权威对照表 —— 而且是官方 API 给的，
不是从别处抄的。

## 二、收益怎么算

```
毛租金   = 日租金 × 持有天数 × 出租率
净租金   = 毛租金 × (1 − 租赁平台抽成)
价格变动 = 买入价 × 持有期涨跌
卖出成本 = (买入价 + 价格变动) × (卖出抽成 + 提现费)
总收益   = 净租金 + 价格变动 − 卖出成本
年化     = 总收益 ÷ 买入价 × 365 ÷ 持有天数
```

**买入价取各平台最低在售价** —— 收益率的分母应该是你实际付出的钱。用均价会把
收益率算低，让不值得的标的看起来还行。

### 两个年化率的区别（最容易搞混的地方）

| 口径 | 计算 | 含义 |
| --- | --- | --- |
| **理论年化** | 日租金 × 365 ÷ 买入价 | **满租**上限，任何平台都达不到 |
| **平台年化** | 数据源直接给的 `lease_annual` | 平台口径，推测已折算空置与租期结构 |

两者的比值被用作「**隐含出租率**」的估计：

```
出租率 ≈ 平台年化 ÷ 理论年化
```

⚠ 这是**推算值**，平台的确切算法未公开。代码里字段带 `implied_` /
`occupancy_assumed` 前缀，输出里也总是带这条提醒。

当平台没给年化率时，用**保守的 60% 假设**而不是 100%。理由很直接：
空置是租赁的常态而非例外 —— 上架后要等租客、租期之间有空档、淡旺季差异很大。
按满租估算会系统性高估收益。

## 三、为什么「日租金高」不等于「收益高」

一个真实样本（CSQAQ 官方文档数据，M9 刺刀多普勒）：

```
短租日租金 4.14   长租日租金 3.55      ← 短租日租金更高
短租年化   11.92%  长租年化   14.05%    ← 但长租年化更高
```

**原因在空置率**：短租租期碎、等待期多；长租租期连续、几乎无缝衔接。
折算出租率后（53% vs 72%），长租的实际租金收入反而更多。

只看日租金会直接选错。

---

## 四、持有周期会让结论反转

同一件饰品、同样的租金，不同持有周期的结论完全不同：

```
M9 刺刀多普勒（真实数据）

长租   30 天    -125.4%      ← 30 天跌了 8.13%，租金完全不够填
长租   90 天     -20.8%      ← 90 天跌 4.92%，仍不够
长租  180 天     +50.0%      ← 180 天涨 22.73%，租金叠加后转正
```

**因为租金是线性累积的，价格变动不是。** 这个结构性差异是本模块存在的主要理由 ——
单看「年化 14%」会以为稳赚，实际持有 90 天是亏的。

## 五、结论分档与必带提醒

| 年化 | 结论 |
| --- | --- |
| ≥ 25% | 值得考虑 |
| ≥ 10% | 勉强可行 |
| < 10% 或为负 | 不建议 |

除了收益，还会检查：

- **流动性**（存世量 / 在售量 / 成交量）—— 低于 20 分提示「卖出可能要压价」
- **出租竞争**（出租挂单 ÷ 在售量 > 50%）—— 提示空置率可能高于推算值
- **风险调整收益**（年化 ÷ 年化波动率）—— 低于 0.5 提示「波动相对收益偏高」

结论里**必定附带**两条提醒：

> ! 出租率由平台年化率推算，平台算法未公开；实际空置可能更高
> ! 价格趋势为历史外推，赛事/版本更新等外部事件无法预判

## 六、费率必须按你的实际档位改

租赁收益对手续费极其敏感：**日租金常常只有价格的 0.05–0.2%，而一次卖出抽成 2.5%
—— 相当于吃掉十几天的租金。**

默认值只是常见档位，请按自己的会员等级覆盖：

```python
from csmon import rental

result = rental.analyze(
    snapshot, horizon_days=90, mode=rental.MODE_LONG,
    rent_fee={"YOUPIN": 0.08},        # 租金抽成
    sell_fee={"YOUPIN": 0.015},       # 卖出抽成
    withdraw_fee=0.01,                # 提现费
)
```

费率填错会让结论反向，所以每次报告都会把用到的费率口径打印出来。
