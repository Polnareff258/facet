# 饰品变体与中文名

本文说明「同一种饰品的不同变体」在本工具里是怎么建模的，以及为什么其中一部分
能可靠分类、另一部分必须靠实测学习。

---

## 一、先把边界划清楚：变体分两类

这是整个机制的地基，也是最容易做错的地方：

| 变体类型 | 由什么决定 | 能否从名称确定 | 本工具的处理 |
| --- | --- | --- | --- |
| **磨损档**（崭新/略磨/久经/破损/战痕） | 名称后缀 | ✅ 能 | 直接解析，100% 可靠 |
| **品质**（普通 / 暗金 StatTrak™ / 纪念品 Souvenir） | 名称前缀 | ✅ 能 | 直接解析 |
| **星标**（★ 匕首 / 手套） | 名称前缀 | ✅ 能 | 直接解析 |
| **多普勒相位**（红宝石/蓝宝石/黑珍珠/P1-P4） | 饰品实例的 `paint_seed` | ❌ 名称里没有 | **平台词表**（悠悠 `specialStyle`） |
| **伽马多普勒**（绿宝石/P1-P4） | 同上 | ❌ | 同上 |
| **渐变百分比**（80%~100%） | 同上 | ❌ | **平台词表**（悠悠 `fadeText`） |
| **大理石渐变档位**（冰火/红头/蓝尖/金） | 同上 | ❌ | 平台词表（有则采，无则留空） |
| **表面淬火档位**（T1-T4） | 同上 | ❌ | **平台词表**（悠悠 `specialStyle`） |
| **特殊模板**（如 AK-47 淬火 #661） | 同上 | ❌ | `paint_seed` 实测学习（辅助） |

**关键事实**：Steam 的 `market_hash_name` 里**没有**相位、渐变百分比、淬火档位。
一把 `★ 蝴蝶刀 | 多普勒 (崭新出厂)` 在 Steam 上只是一个名字，
它的实际档位由这件**具体饰品的 `paint_seed`** 决定。

好消息是：**平台自己已经分好档了**，而且给的是中文标签。所以本工具不从名称猜、
也不靠抄种子表，而是直接把平台的档位词表采下来。

---

## 二、名称层：确定性解析

`csmon/skins.py` 把名称解析成结构化变体：

```
★  StatTrak™  AK-47 | Redline  (Field-Tested)
│   │         │                 └─ 磨损（5 档，精确匹配）
│   │         └─ 武器 | 皮肤
│   └─ 品质（普通 / 暗金 / 纪念品）
└─ 星标（匕首、手套）
```

解析要处理的边界（都有测试覆盖）：

- `Sticker | Titan (Holo) | Katowice 2014` —— 括号在中间，**不是**磨损
- `Sticker | Titan (Holo)` —— 括号在末尾但内容不是已知磨损，**不切**
- `Music Kit | ...`、`Sticker | ...` —— 带竖线但**没有磨损档**（首段是 weapon 不是 category）
- `★ StatTrak™ Karambit | Doppler (Factory New)` —— 星标与暗金同时存在

解析失败不抛异常：未知格式照样进库（`parsed=False`），因为市场一直在加新东西，
宁可显示得粗糙也不能丢数据。

### 变体展开

你只需要给出基础名，工具负责展开成具体变体：

```bash
python -m csmon focus add "AK-47 | Redline" --intent buy --target 95 --wears FT,MW
# → AK-47 | Redline (Field-Tested)
# → AK-47 | Redline (Minimal Wear)
```

`--wears` 接受英文缩写（FN/MW/FT/WW/BS）或中文（崭新/略磨/久经/破损/战痕）；
`--qualities` 接受 普通/暗金/纪念品。展开时会自动防止重复前缀（不会出现 `★ ★`）。

## 三、图案层：档位词表来自平台，不靠自己推算

### 实测发现（这是本模块的转折点）

悠悠有品的公开求购接口**直接返回平台自己分类好的中文档位名**，而且是免凭据的：

| 字段 | 实测取值 | 含义 |
| --- | --- | --- |
| `specialStyle` | `红宝石` `蓝宝石` `黑珍珠` `绿宝石` `P1` `P2` `P4` `T1` `T2` | 离散档位（宝石 / 相位 / Tier） |
| `fadeText` | `99-100` `97-99` | 渐变百分比区间 |
| `abradeText` | `0-0.01` `0.07-0.08` `0.15-0.24` | **比 5 档更精细**的磨损区间 |
| `commodityName` | `刺刀（★） | 多普勒 (崭新出厂)` | 官方中文名 |

三样东西一次拿到，其中档位名是平台权威分类 —— 这比从 `paint_seed` 反推可靠得多。

### 档位价差有多大（实测，求购价）

```
★ 刺刀 | 多普勒 (崭新出厂)
  黑珍珠  ¥12,310      ← 宝石档
  红宝石  ¥11,020
  蓝宝石   ¥7,400
  P2       ¥2,990
  P4       ¥2,490
  P1       ¥2,400      ← 最低档

AK-47 | 表面淬火 (久经沙场)
  T1       ¥6,880
  T2       ¥2,440

AWP | 渐变之色 (崭新出厂)
  渐变 99-100  ¥4,550
  渐变 97-99   ¥4,400
```

**宝石档是最低档的 5 倍，淬火 T1 是 T2 的 2.8 倍。** 把「同一把刀」当一个商品定价，
等于把一辆车和它的发动机当同一个东西卖。

### BUFF 侧为什么做不到

实测结论（`probe/probe_buff_variants.py` 可复现）：

| BUFF 请求 | 匿名结果 |
| --- | --- |
| `sell_order` 基础查询 | ✅ `code=OK` |
| `sell_order?paintseed=N` | ❌ `Login Required` |
| `sell_order?min_paintwear=N` | ❌ `Login Required` |
| `sell_order?sort_by=...` | ❌ `Login Required` |
| `sell_order?paintwear=N`（单值） | ✅ `code=OK` |
| `sell_order?search=...` | ✅ `code=OK` |

**带档位筛选的查询一律需要登录。** 另外试了 8 个候选的档位列表端点
（`goods/paintseed` / `goods/pattern` / `goods/special_style` …）全部 `Path Not Found`；
商品页 HTML 里也搜不到档位定义。
匿名在 BUFF 侧只能拿到挂单明细里的 `paint_seed` **原始数字**，拿不到档位名称。

> 结论：档位维度**以悠悠为准**；BUFF 的 `paint_seed` 仅作辅助（可用于同档位内的磨损排序）。

### 怎么用

```bash
# 1. 采集档位词表（每个饰品几秒钟）
python -m csmon variants sync "★ M9 Bayonet | Doppler (Factory New)"
# 或批量采集所有变体敏感且已有 templateId 的饰品
python -m csmon variants sync --limit 40

# 2. 查看某饰品有哪些档位
python -m csmon variants show "★ M9 Bayonet | Doppler (Factory New)"
```

```bash
# 3. 开启档位级求购价监控（config.yaml）
youpin_direct:
  tier_mode: true       # 按档位分别产出求购价
  tier_pages: 2         # 每项抓取页数
```

开启后，同一把刀会产出多条报价，各自带 `variant_label`：

```
★ Bayonet | Doppler (Factory New)
  红宝石   求购 ¥11,020
  蓝宝石   求购  ¥7,400
  P2      求购  ¥2,990
```

同时会补一条 `variant_label=None` 的**整品汇总**报价（取档位中的最高求购价），
用于和 CSQAQ / SteamDT 的整品口径对齐做跨平台比价。

**注意区分**：整品汇总价代表「有买家愿意为最好的档位出多少」，
**不等于**「整品的普遍求购价」—— 它只用于横向对比，不用于判断单品价值。

### 冷门档位要多拉几页

平台不提供静态档位清单，「买家实际挂出的档位约束」就是这个品类真实在流通的档位集合。
样本越多覆盖越全：实测刺刀多普勒第一页 41 条里没有 P3 相位，`--pages 3` 才可能覆盖到。

### 关于 `paint_seed` 反推（保留但降级为辅助）

早期做法是「从挂单的 `paint_seed` + 价格分布反推哪些种子贵」。
现在有平台权威词表，这条路径降级为辅助手段，实现仍保留在 `csmon/patterns.py`：

```bash
python -m csmon patterns learn "饰品名"   # 抓挂单 → 按种子聚合价格 → 标出溢价种子
```

它在两种情况下仍有用：
1. 你想知道**同一档位内**哪些具体模板（如淬火蓝钢的 #661）更值钱
2. 平台词表没覆盖到的品类

## 四、中文名

### 为什么不翻译，而是学习

CS 饰品的中文名是**社区约定**，不是英文逐词直译：

| 英文市场名 | 中文名 |
| --- | --- |
| `★ M9 Bayonet \| Bright Water (Well-Worn)` | `M9 刺刀（★） \| 澄澈之水 (破损不堪)` |
| `AK-47 \| Redline (Field-Tested)` | `AK-47 \| 红线 (久经沙场)` |
| `AWP \| Asiimov (Field-Tested)` | `AWP \| 二西莫夫 (久经沙场)` |

注意星标的位置：英文在**前**（`★ M9 Bayonet`），中文在**名后**（`M9 刺刀（★）`）。
这种语序差异规则推不出来，所以正确做法是从权威源学。

### 三层来源，按可信度降级

| 来源 | 含义 | 怎么来的 |
| --- | --- | --- |
| `learned` 官方 | 权威源直接给的中文名 | BUFF `goods/info` 的 `name`、CSQAQ 的 `name` |
| `derived` 派生 | 同皮肤其它磨损档的中文基础名 + 磨损译名 | 自动复用 |
| `composed` 拼装 | 完全按英文结构拼 | 兜底，语序可能不地道 |

**中文名在采集时自动回收**，不额外发请求 —— CSQAQ 与 BUFF 的响应里本来就带中文名，
适配器把它放进 `SourceQuote.raw`，落库前顺手收录。这一点很重要：
额外请求要花 API 限额，还可能触发风控。

磨损只有 5 档，而皮肤有上万个 —— 所以学到「久经沙场」的中文名后，
同皮肤的「崭新出厂」也能显示中文（`derived`），不必为每个变体查一次。

```bash
python -m csmon names stats                              # 覆盖率与来源分布
python -m csmon names show "AK-47 | Redline (Factory New)"  # 看具体条目
python -m csmon names set "英文名" "正确中文名"            # 手工更正（优先级最高）
```

手工录入的优先级最高，**不会被自动收录覆盖** —— 你纠正一次就永久生效。

## 五、关注清单：带交易意图

`focus` 与通用 `watchlist` 是两层，用途不同：

| | watchlist | focus |
| --- | --- | --- |
| 目的 | 泛化盯盘，找机会 | 我确定要买/要卖的 |
| 意图 | 无 | 买入 / 卖出 / 观察 |
| 价格 | 触发阈值 | **目标价 + 预算 + 数量** |
| 筛选 | 无 | 可接受的磨损 / 品质 / 档位 |

```bash
python -m csmon focus add "AK-47 | Redline" --intent buy \
        --target 95 --budget 400 --wears FT,MW --priority 1 --note "等回调"
python -m csmon focus ls
python -m csmon focus detail "AK-47 | Redline (Field-Tested)"
```

状态判定的语义（买入方向）：

| 状态 | 条件 |
| --- | --- |
| 达到买点 | 现价 ≤ 目标价 |
| 接近买点 | 现价 ≤ 目标价 × 1.05 |
| 等待回落 | 更高 |
| 无数据 | 该变体还没采到报价 |

卖出方向对称（现价 ≥ 目标价即达标，且优先看**求购价** —— 那是能立刻成交的价）。

看板「关注」页会按意图分组展示，并把已达标的高亮出来。

## 六、给 LLM 的上下文里包含什么

`csmon advice ask` 会把下面这些结构化数据送给模型：

- 饰品的完整解析（武器/皮肤/磨损/品质/星标/是否变体敏感品类）
- 当前各平台在售价、在售量、求购价
- 技术指标全量（MA/RSI/布林/波动率/年化/回撤/Z 值）+ 文字解读
- 近 30 根日线 OHLC
- **同皮肤的磨损阶梯**（其它磨损档的现价）—— 判断「这个档位贵不贵」
- 跨平台价差
- 图案档位判定与已观测到的溢价种子
- 你自己的关注设置（意图、目标价、预算）
- 近期告警与极致追踪采样

提示词里明确要求模型：只能依据这组数据判断，数据里没有的不许假设；
必须给出**反面证据**与**风险**；不许使用「保证收益」类表述。
输出被强制为固定 JSON schema，并连同数据指纹一起落库 —— 价格变了就知道建议过期了。
